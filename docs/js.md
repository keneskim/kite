# JavaScript 后端

同一个 `.kite` 程序，可以翻译成 JavaScript。

```
python3 kite.py 程序.kite --js
→ 生成 程序.js
```

```
node 程序.js
```

也能直接丢进网页：

```html
<script src="程序.js"></script>
```

---

## 和 C 版的关系

回归测试在 C 和 JS 上使用同一份预期输出，涵盖：

- 中文输入（`ask`）
- 固定种子的随机数（`seed(7)` 出来的序列和 C 一样）
- 越界报错文案
- 二维表和打印格式

怎么做到的：随机数用 BigInt 复刻了 C 那边的 64 位 xorshift，所以种子相同、序列相同。

---

## 支持什么

**语言全都支持**：`if`、`rp` 四种循环、函数、数组、`push`、切片、二维表、字符串插值、40 个内置函数里的绝大部分。

平台限制：

| 不支持 | 原因 |
|---|---|
| `serve` / `form` / `html` | 那是 C 后端的本地 HTTP 服务 |
| 在浏览器里用 `ask` `read` `write` | 浏览器没有文件系统和标准输入 |

Node 可以使用标准输入和文件操作。浏览器没有标准输入和本地文件 API。

---

## 和 C 版的小差异

| | C 版 | JS 版 |
|---|---|---|
| 数字 | double | double（一样） |
| 数字输出 | 最多 15 位有效数字 | 最多 15 位有效数字 |
| 数组打印 | `[1, 2, 3]` | `[1, 2, 3]`（一样） |
| 文本数组 | `["a", "b"]` | `["a", "b"]`（一样） |

文本位置按 Unicode 码点计算。大小写转换会受目标运行时影响。

---

## 为什么 JS 这个后端便宜

kite 的语义（数字=浮点、文本=字符串、数组、1 起下标）和 JS 几乎一一对应，所以代码生成器只要 **700 行**，不用写内存管理、不用写字符串运行时。

对比：C# 后端 550 行但只支持子集；C 后端 2800 行还要附带一份 C 运行时。

---

## 测试

```
python3 tests/run.py --backend js
```

它会：把每个测试程序编译成 JS → 用 node 跑 → 和 C 版的期望输出**逐字比对**。
